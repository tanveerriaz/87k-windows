# 87K Windows — Frontend Architecture Audit

Principal Engineer review · read-only · repo state on disk (includes uncommitted `landing-page.tsx` / `global.css` changes)
Scope: `src/client/**`, `vite.config.ts`, `index.html`, `tests/e2e/demo.spec.ts`, plus the server touchpoints the client depends on.

## Summary

The client is small, typed end-to-end against `src/shared`, and the Canvas wall is genuinely well engineered. The risk is concentrated in latency and stage-machine correctness. The landing page now ships a 6.8 MB autoplaying film on top of a 1.9 MB PNG background — roughly 9 MB before a phone reaches the first button. During a 20–35 s local Gemma extraction the participant sees a static panel with no elapsed time, timeout, or cancel. A listener who hits `NO MATCH YET` is bounced into the storyteller's capture form. Socket acks and `room:error` never surface to participants. The uncommitted landing change breaks an e2e test.

### Verified as compliant / not a finding

- **The optional photo genuinely never leaves the browser.** `compressImage` (`lib/image.ts:4-24`) is pure client-side canvas work; both call sites send `photoData: null` explicitly (`join-page.tsx:129, 184`), and the preview renders from the in-memory data URL (`:374`). The server-side branch at `app.ts:108-109` is a live but unused path — worth deleting so it cannot be re-wired by accident, but the current claim is honest.
- **No secrets or privileged config reachable from the client.** Zero `VITE_` references anywhere in `src/` or `vite.config.ts`; the only client→server surface is `/api/extract` plus the typed socket events. `admin-page.tsx` renders only room state and asserts as much at `:41`.
- **Provider status is visible and honest.** `StatusBadge` (`components/status-badge.tsx:9-33`) is on all three live surfaces and `provider-presentation.ts:42-49, 67-74` labels mock as "Development test harness … never judging" — asserted at `demo.spec.ts:134-135`.
- **Canvas, not 87k DOM nodes.** A single `<canvas>` (`hdb-wall-canvas.tsx:216-223`); only lit windows are drawn.
- **No layout shift from the new video** — `global.css:2042` reserves `aspect-ratio: 16/9` via `:has(video)`.
- **Route-level code splitting is correct**: `app.tsx:4-7` lazy-loads all four routes; the wall never pays for `qrcode` (33 KB admin chunk) and the landing chunk is 4.2 KB.
- **Invalid-model-output and no-match states exist and are wired** (`app.ts:38-43` → `join-page.tsx:405`; `join-page.tsx:508-517`; `wall-page.tsx:100-107`).

## Top 3 mandated changes

1. **Fix the listener no-match bounce and put the stage machine under one reducer** *(finding #2 — effort: **M**)*. Immediate patch is small (guard `join-page.tsx:59` with `!listenerEntry`, effort **S**), but four `useEffect`s racing to `setStage` over shared room state (`join-page.tsx:52-92`) will keep producing this class of bug. Collapse them into a single `deriveStage(role, phase, consent, myDecision, isSource)` pure function — mirroring the pattern `lib/wall-visual-state.ts` already establishes for the wall — and unit-test it. Add the missing listener assertion to `demo.spec.ts:91-120`.

2. **Make the participant's wait honest and bounded** *(findings #3, #4, #5, #6, #7 — effort: **M**)*. Take Gemini off the consent critical path (`rooms.ts:157-178` → emit consent first, push `guide:ready` when it lands); add elapsed-time + expected-duration + cancel to the processing panel that does not depend on CSS animation; use `socket.timeout()` on the `approve`/`decide` acks with pending button states; render `room.message` on join and wall; map `ApiError.code` (especially `LOCAL_GEMMA_BUSY`) to a retry affordance instead of leaking raw `SyntaxError`/`ZodError` text.

3. **Cut the landing page from ~9 MB to under 1 MB before first interaction** *(findings #1, #9, #14 — effort: **S**)*. Remove `autoPlay`, set `preload="none"`, re-encode `landing-story.mp4` to <3 MB with a 480p source, replace the 1.9 MB `photographic-hdb-wall.png` background with a right-sized WebP/AVIF, delete the orphaned 1.9 MB `public/assets/two-chairs-hero.png`, and repair `demo.spec.ts:19`. This is the single highest ratio of demo risk removed to hours spent.

## One thing done better than the standard approach

**The Canvas wall was made observable without giving up Canvas.** The usual outcome of "use Canvas, not 87,200 DOM nodes" is a surface no test can assert on, followed by either brittle pixel diffs or no coverage at all. Here the visual state is first extracted as a *pure function* — `lib/wall-visual-state.ts:9-23` maps a `RoomSnapshot` to `{state, litWindowIds, hasThread}` with no React, no canvas, no timing — and then re-published as data attributes on the canvas element itself (`hdb-wall-canvas.tsx:219-222`: `data-wall-state`, `data-lit-count`, `data-has-thread`). Playwright asserts against those directly (`demo.spec.ts:51, 55, 61-62`), so "the wall is in `matching` and has no thread yet" is a hard assertion in the two-tab critical flow, and the same derivation is unit-testable in isolation. The imperative drawing code stays imperative; the semantics stay declarative and verifiable. The `aria-label` at `:222` is generated from the same derived state, so the accessible name cannot drift from the pixels.

A second, smaller instance of the same care: the reduced-motion override (`global.css:1949-1962`) collapses `animation-duration` rather than setting `animation: none`, which preserves `animation-fill-mode: forwards` — so the evidence chips at `global.css:1214-1215`, which start at `opacity: 0`, still end up visible. The naive `animation: none !important` version of that rule would have left the wall's evidence path permanently invisible to every reduced-motion viewer.
